## 1. Введение и постановка задачи

- **Цель проекта:** предсказать скорость пристройства животных из приютов (`AdoptionSpeed`) по табличным признакам.
- **Формулировка задачи:** мультиклассовая классификация.
- **Обоснование метрики качества:** основной метрикой выбрана **Macro F1**, так как классы распределены неравномерно, а метрика одинаково учитывает качество по каждому классу. `Accuracy` используется как вспомогательная.

---

## 2. Поиск и описание данных

- **Источник данных:** [Kaggle PetFinder.my Adoption Prediction](https://www.kaggle.com/competitions/petfinder-adoption-prediction/data). Датасет выбран как реальная прикладная задача с разными типами признаков (числовые и категориальные).
- **Объём:** `14993` строк и `24` исходных столбца.
- **Типы признаков:** `int64` (19), `object` (4), `float64` (1).
- **Целевая переменная:** `AdoptionSpeed` (5 классов от 0 до 4).

---

## 3. Обработка и подготовка данных

- **Пропуски:** обнаружены в `Name` (`1265`, около `8.44%`) и `Description` (`13`, около `0.09%`).
- **Дубликаты:** точных дубликатов не обнаружено (`0`).
- **Выбросы:** выполнена IQR-оценка для числовых признаков; наиболее выражены `Breed1`, `Age`, `PhotoAmt`. Для baseline-версии агрессивное удаление не применялось, чтобы не потерять редкие валидные наблюдения.
- **Типы данных:** категориальные поля приведены к строковому типу для стабильной обработки.
- **Feature engineering:**
  - исходно: `24` признака;
  - добавлены признаки `NameLength`, `HasName`, `FeePerPhoto`;
  - после генерации признаков получено `27` столбцов (в признаки `X` попадает `26`, целевая переменная выделена отдельно).
- **Визуализации:** построены графики распределения таргета, boxplot для `Age` и `Fee` по классам, распределение `HasName` по `AdoptionSpeed`.
- **Split и anti-leakage:**
  - использован stratified split `train/val/test = 60/20/20`;
  - `random_state=42` для воспроизводимости;
  - проверена близость долей классов во всех частях выборки;
  - все трансформации (импутация, масштабирование, OneHotEncoding) обучаются только на train в составе пайплайна.

---

## 4. Baseline-модель

- **Модель:** `LogisticRegression` (как baseline из коробки).
- **Результаты:**
  - `val_accuracy = 0.425142`
  - `val_macro_f1 = 0.326553`
  - `test_accuracy = 0.426809`
  - `test_macro_f1 = 0.332600`
- **Роль baseline:** точка отсчета для сравнения с ансамблями и моделями после тюнинга.

---

## 5. Эксперименты

Выполнено сравнение 5 моделей, для части моделей применен `GridSearchCV` (cv=3, scoring=`f1_macro`).

| Модель | Гипотеза | Параметры / setup | val_macro_f1 | test_macro_f1 |
|--------|----------|-------------------|--------------|---------------|
| `extra_trees` | более случайный ансамбль уменьшит variance | `no_tuning` | `0.345973` | `0.348001` |
| `random_forest` | ансамбль деревьев устойчив к шуму | tuned (`n_estimators`, `max_depth`, `min_samples_leaf`) | `0.331667` | `0.334234` |
| `gradient_boosting` | бустинг улучшит качество по Macro F1 | `no_tuning` | `0.330179` | `0.346062` |
| `logreg_baseline` | линейная модель задает нижнюю границу качества | `no_tuning` | `0.326553` | `0.332600` |
| `knn` | локальная близость объектов может помочь | tuned (`n_neighbors`, `weights`) | `0.291337` | `0.288098` |

Итог: ансамбли деревьев показали более высокое качество по сравнению с baseline и `KNN`.

---

## 6. Финальная модель и интерпретируемость

- **Выбранная модель:** `ExtraTreesClassifier`.
- **Почему выбрана:** имеет лучший `val_macro_f1 = 0.345973` и стабильный результат на тесте `test_macro_f1 = 0.348001`.
- **Интерпретация:** для деревьев решений интерпретация возможна через feature importance; в текущей версии проекта акцент сделан на сравнении моделей и воспроизводимом пайплайне.
